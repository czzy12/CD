# 文字字段与来源规则

> 本文件保存跨来源标准文字字段、来源专属字段和文件元数据规则。字段决策状态仍以人工确认工作簿为准。

<a id="field-001"></a>

## 2026-07-18 统一标准文字字段映射第一步

- 入口：`bankflow_v2/models.py` 的 `Transaction` 与 `map_standard_text_fields()`。
- 标准字段：交易对手名称/账号/银行，摘要、备注、用途、交易类型，商户名称/类别/地点，以及字段来源、字段置信度和人工复核信息。
- 映射依据：只使用 `raw_headers` 与 `raw_fields` 的同列精确表头同义词；表头允许 Unicode 形式、空白和常见分隔符差异。
- 保守边界：不从 `raw_text` 猜测；不拆分 `摘要/备注`、`对方账号/户名` 等混合列；缺失、空值或不可靠字段保持空。
- 优先级：解析器显式传入的非空标准字段优先，自动映射不得覆盖；显式 `field_sources` 和 `field_confidence` 同样保留。
- 来源口径：自动映射来源记录为 `raw_headers[列号]:原表头`；置信度 `1.0` 仅表示精确表头同列映射，不代表原 PDF 内容已经人工核真。
- 兼容性：新增字段位于 `Transaction` 旧字段之后，既有位置参数、解析器、数字汇总和余额校验不变。

## 2026-07-19 微信、支付宝确认文字字段

- 统一模型新增：`transaction_direction`（收支方向原文）、`transaction_method`（交易方式）、`payment_method`（付款方式）、`product_description`（商品说明）。四者含义独立，不互相合并。
- 微信真实表头：`交易单号 / 交易时间 / 交易类型 / 收/支/其他 / 交易方式 / 金额(元) / 交易对方 / 商户单号`。
- 微信标准字段：交易时间、交易类型、收支或其他、交易方式、金额、交易对方；`其他` 保留整笔记录但不计入数字汇总。交易单号、商户单号只保留在 `raw_fields/raw_headers`，不作为分析字段。
- 支付宝固定表头：`收/支 / 交易对方 / 商品说明 / 收/付款方式 / 金额 / 交易订单号 / 商家订单号 / 交易时间`。
- 支付宝标准字段：收支、交易对方、商品说明、付款方式、金额、交易时间；`不计收支` 保留整笔记录但不计入数字汇总。交易订单号、商家订单号只保留在 `raw_fields/raw_headers`，不作为分析字段。
- 字段来源继续记录为 `raw_headers[列号]:原表头`，精确同列映射置信度为 `1.0`；空字段保持空，多行字段规范为单个空格，不从 `raw_text` 猜测。

## 2026-07-19 富滇银行确认字段实现

- 确认依据：`富滇银行文字字段确认.xlsx` 的 `确认字段!A4:G28`；21 项状态确认保留原建议，`currency / account_currency / verification_code` 明确排除，电子印章和验真说明按原建议排除。
- 通用文件容器：富滇解析器返回列表兼容的 `TransactionList`，文件级字段保存在 `StatementMetadata`，不重复写入每笔交易。
- 逐笔标准字段：`source_sequence / transaction_time / income / expense / raw_amount / balance / raw_balance / counterparty_account / counterparty_name / summary / remark / merchant_name`。
- 富滇来源专属字段保存在 `Transaction.source_fields`：`merchant_code / merchant_name_and_address_raw / secondary_merchant_info / postscript / remark_details`。
- 备注拆分边界：只识别明确标签 `商户代码 / 商户名称及地址 / 二级商户信息 / 附言 / 商户 / 商品 / 摘要 / 车牌`；已知字段确定性映射，其余带标签内容和标签前原文进入 `remark_details`，完整备注仍保留，不从无标签文本猜测。
- 账户和文件级字段：`account_name / account_number / statement_period_start / statement_period_end / generated_at / source_part_label / page_total`，均记录原始值、字段来源和置信度。
- 排除边界：交易币种仍存在于九列 `raw_fields` 作为原始证据，但不建立 `currency` 分析字段；账户币种、验证码、电子印章和验真说明不进入 `StatementMetadata`。

## 2026-07-19 初步跨来源字段归类

- 映射口径：标准字段仅使用 `raw_headers / raw_fields` 同列精确表头；来源专属字段仅在解析器拥有确定语义时写入 `Transaction.source_fields`，同时保留来源和置信度。不得根据 `raw_text`、混合列或位置猜测字段含义。
- 已扩充的标准表头包括序号、收付方名称/账号、对方开户行、收支状态、借贷标志、付款方式和商户地点；`交易地点` 不自动映射为商户地点。
- 已统一归类的来源证据字段包括核心/交易流水号、交易凭证号、凭证号码/种类、记账/会计日期、明细标注、交易描述、交易网点、来源、全局路由号和卡号。
- 已确定的解析器补充：华夏银行对公、河北农信、邮储银行对公、交通银行对公、上海银行对公；客户明细对公的未拆分交易文本保留为来源专属原文，不再误作交易对手名称。
- 待确认项及字段覆盖检查见 `D:\Investigator PDF\outputs\field-classification-initial\初步字段解析与归类清单.xlsx`；其中的币种、渠道/方式、地点、摘要备注和对手方混合列必须逐来源确认后再实现。

## 2026-07-19 已确认 10 类来源文字字段

- 工商银行个人：固定 13 列保留摘要、对方户名、储种、渠道和序号；逐笔本方账号、币种、钞汇、地区及对方账号不进入分析字段。
- 建设银行个人：固定 7 列保留摘要、“交易地点/附言”完整原值及“对方账号与户名”完整原值；后者仅在唯一 `/` 边界存在时取斜杠后户名，不写对方账号。
- 兴业银行：固定 9 列映射摘要、支/收、交易用途和对方户名；“对方账户/对方银行”只作为混合来源字段完整保留。
- 民生银行对公：日期行和时间行确定性配对为 10 列；摘要、对方行名进入标准字段；“对方户名/账号”只在唯一 `/` 时拆分，凭证类型、凭证号码和流水号只作证据字段。
- 平安银行个人：固定 8 列映射摘要、备注和序号；交易地点为来源专属字段，交易对手信息完整保留且不拆分。
- 浦发银行个人：固定 9 列映射交易名称和对手姓名；对手账号、无效交易摘要及逐笔本方账号不进入分析字段，本方户名、账号和查询区间进入文件元数据。
- 浦发银行对公：固定 9 列映射对手机构、对手名称和备注；摘要代码原样同时保留为交易类型和 `abstract_code`，交易流水号只作证据字段。
- 中信银行个人：文本行按尾部固定三段拆为交易摘要、对方账号和对方户名；无法形成明确三段时只保留尾部原文；户名、账号、查询区间、开户日期和币种原值进入文件元数据或原始证据。
- 招商银行个人：文本行先按固定列取得交易摘要和完整对手信息；仅当末尾是明确账号时拆为账号及此前完整名称。
- 华夏银行个人：以日期词块为行锚点、按固定 x 坐标恢复 9 列；仅映射摘要、附言和来源专属交易机构，对方开户行不因通用表头自动进入分析字段。
- 所有来源继续保留 `raw_headers / raw_fields / raw_text` 和 `field_sources`；未确认或非唯一边界不猜测。

## 2026-07-22 8 项已确认来源文字字段与文件元数据

- 长沙银行对公：`摘要/备注`作为完整来源字段 `summary_remark_raw` 保留在 `source_fields`，不再猜拆为标准 `summary` 或 `remark`。
- 招商银行对公：`票据号/摘要`仅取已确认的摘要部分。纯数字票据号不写入标准字段；纯数字票据号后存在文字时，仅保留该文字为 `summary`。
- 对公客户账户明细：坐标列稳定时，将对方户名、摘要、备注分别写入标准字段；对方账号仅保留为 `counterparty_account_raw` 原始证据，不映射标准对方账号；无法稳定分列时继续保留未拆分交易文本。
- 工商银行对公账户明细清单：仅映射对方单位、摘要和用途；入账日期/记账日期作为来源专属 `posting_date`。对方账号、卡号及补充摘要不进入标准分析字段。
- 农业银行对公、建设银行对公：解析结果使用兼容列表的 `TransactionList` 返回；仅从首页确定性页眉提取户名、账号和查询期间到 `StatementMetadata`，并保留字段来源与置信度。
- 河北银行个人、霸州舜丰村镇银行对公：对方账号只保留为 `counterparty_account_raw` 原始证据，不写入标准对方账号。霸州舜丰优先按实际表头解析，对方户名、开户行、摘要和用途仍按明确列映射。
- 上述规则仅覆盖已人工确认的字段边界；未确认来源、混合列和缺少可靠原件的情形均不以相似版式推断。
