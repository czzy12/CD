# 文字字段与来源规则

> 本文件保存跨来源标准文字字段、来源专属字段和文件元数据规则。字段决策状态仍以人工确认工作簿为准。

<a id="field-001"></a>

## 2026-07-18 统一标准文字字段映射第一步

- 入口：`bankflow_v2/models.py` 的 `Transaction` 与 `map_standard_text_fields()`。
- 标准字段：交易对手名称/账号/银行，摘要、备注、用途、交易类型，商户名称/类别/地点，以及字段来源、字段置信度和人工复核信息。
- 映射依据：只使用 `raw_headers` 与 `raw_fields` 的同列精确表头同义词；表头允许 Unicode 形式、空白和常见分隔符差异。
- 保守边界：不从 `raw_text` 猜测；不拆分 `摘要/备注`、`对方账号/户名` 等混合列；缺失、空值或不可靠字段保持空。
- 优先级：解析器显式传入的非空标准字段优先，自动映射不得覆盖；显式 `field_sources` 和 `field_confidence` 同样保留。
- 来源口径：自动映射来源记录为 `raw_headers[列号]:原表头`；置信度 `1.0` 仅表示精确表头同列映射，不代表原 PDF 内容已经人工核真。
- 兼容性：新增字段位于 `Transaction` 旧字段之后，既有位置参数、解析器、数字汇总和余额校验不变。

## 2026-07-19 微信、支付宝确认文字字段

- 统一模型新增：`transaction_direction`（收支方向原文）、`transaction_method`（交易方式）、`payment_method`（付款方式）、`product_description`（商品说明）。四者含义独立，不互相合并。
- 微信真实表头：`交易单号 / 交易时间 / 交易类型 / 收/支/其他 / 交易方式 / 金额(元) / 交易对方 / 商户单号`。
- 微信标准字段：交易时间、交易类型、收支或其他、交易方式、金额、交易对方；`其他` 保留整笔记录但不计入数字汇总。交易单号、商户单号只保留在 `raw_fields/raw_headers`，不作为分析字段。
- 支付宝固定表头：`收/支 / 交易对方 / 商品说明 / 收/付款方式 / 金额 / 交易订单号 / 商家订单号 / 交易时间`。
- 支付宝标准字段：收支、交易对方、商品说明、付款方式、金额、交易时间；`不计收支` 保留整笔记录但不计入数字汇总。交易订单号、商家订单号只保留在 `raw_fields/raw_headers`，不作为分析字段。
- 字段来源继续记录为 `raw_headers[列号]:原表头`，精确同列映射置信度为 `1.0`；空字段保持空，多行字段规范为单个空格，不从 `raw_text` 猜测。
- 微信“支付扣款银行流水关联”是独立观察：只有微信来源已由姓名、完整身份证号和微信号三项确认归属，且交易方式银行卡尾号唯一对应可靠完整银行抬头账户时，才可按同日、精确同额、银行文字同时含“财付通/微信支付”和唯一商户组成部分建立候选；歧义不强配。它不进入 v1C/v1D，也不表示账户互转或资金关系。支付宝对应字段尚待原件确认，当前不自动关联。
- 微信首页三要素只读取第 1 页的明确 `兹证明 / 居民身份证或身份证号 / 微信号` 标签；三者任一缺失、掩码、格式不完整或多候选时不形成来源身份。交易方式中的 `储 蓄卡 / 信 用卡 / 银 行卡`字间空格按同一明确标签处理。微信扣款关联可使用可靠完整银行抬头账户作为专用资金账户来源，但不改变 v1C/v1D 对已确认账户和角色的要求。
