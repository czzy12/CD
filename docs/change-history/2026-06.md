## 2026-06-03 GUI 增加流水可信度提示

### 更新前问题

部分未识别银行会走通用识别；部分已测试银行虽然整体解析正确，也可能因为少量可复核提示让用户难以判断整份流水是否可靠。原 GUI 顶部只有文件、流水、收入、支出、异常，不能表达“异常虽有但整体可信”或“通用识别需重点复核”的差异。

### 解决方式

- 在 GUI 顶部汇总栏新增 `可信度` 字段，放在 `异常` 右侧。
- 显示短格式：`高 96%`、`中 82%`、`低 58%`。
- 颜色按等级区分：高为绿色，中为橙色，低为红色。
- 可信度只在 GUI 显示，不写入 Excel 导出，不影响解析逻辑。
- 计算逻辑综合考虑：
  - 专用银行解析或通用识别的基础分。
  - 银行识别置信度。
  - 异常提示数量与级别。
  - 期初余额、期末余额是否存在，且余额链是否连续。
  - 当前日期筛选范围最后两个月是否都识别到流水；如果关闭日期筛选，则按识别到的最新流水月份向前取两个月。
- 2026-06-03 追加调整：`日期范围内没有流水` 只保留在原异常栏提示，不参与可信度评分；最后两个月都有流水作为加分项，没有则不扣分。
- 2026-06-03 追加调整：月度统计 GUI 显示去掉 `期初余额(万元)`、`期末余额(万元)` 两列；启用 `收入调整（微信）` 或 `收支平衡调整（个/公）` 后，月度表仍先保留按流水类型分组的原始统计，下面再显示 `全部` 调整统计。Excel 导出保持原字段。
- 2026-06-03 追加调整：GUI 不再显示 `流水明细` tab，但导出 Excel 仍保留流水明细；可信度对微信流水不再要求期初/期末余额，避免天然无余额列的微信样本被压到 98%。
- 2026-06-04 追加调整：`D:\Codex data\CD_assets\PDF流水\打包测试\城商行\兰州银行.pdf` 未识别且通用识别也没有流水时，可信度显示为 `低 0%`。

### 修改位置

### 背景

完全识别且没有任何异常、没有复核提示时，原来仍显示为 `高`。业务上希望这类结果和普通高可信结果区分开。

## 2026-06-06 GUI 可信度改为等级显示并增强闭合校验

### 更新前问题

GUI 顶部可信度显示为 `高 96%`、`中 82%`、`低 58%` 这类百分比形式。该分数本质是启发式评分，不是精确概率，容易让用户误解为可量化准确率。

同时，原可信度已经考虑余额连续性和最近两个月是否有流水，但没有单独提高下面这个财务闭合关系的权重：

```text
收入合计 - 支出合计 = 期末余额 - 期初余额
```

### 解决方式

- GUI 顶部可信度只显示等级：`极高 / 高 / 中 / 低 / 未识别`。
- 底部摘要文案同步去掉具体百分比。
- 内部仍保留分数用于等级判断，不写入导出。
- 未识别且没有解析到流水时，可信度等级显示为 `未识别`。
- 当流水需要余额且期初/期末余额存在时：
  - 若 `净额 == 期末余额 - 期初余额`，提高加分权重。
  - 若不闭合，扣分。
  - 若闭合且无 `余额不连续` 需复核，视为强可信信号。
- 最近两个月判断从单纯“都有流水”细化为：
  - 最近两个月都有流水：小幅加分。
  - 最近两个月各自月度收支余额闭合且无 `需复核`：额外加分。
  - 最近两个月没有流水：仍不扣分。
- 微信流水和余额可选流水继续跳过余额闭合要求。

### 修改位置

- `gui_v2.py`
- `PROJECT_CONTEXT.md`
- `PROJECT_STATUS.md`
- `技术变更记录.md`

### 验证结果

已验证：

- `python -m py_compile gui_v2.py` 通过。
- 中信对公专用解析无异常时，可信度等级按最新口径显示为 `极高`。
- 合成未识别无流水结果可信度等级为 `未识别`。
- `python tools\regression.py --all --allow-missing` 通过，结果 `25 PASS / 0 FAIL / 5 SKIP`。

- 补齐 `QTableWidget::item:selected`、`QLineEdit/QDateEdit:disabled`、`QCheckBox:disabled`、`QPushButton:disabled` 等前景色和背景色。
- 新增 `assets/check.svg`，保证自定义 checkbox 在固定样式下仍显示勾选标记。
