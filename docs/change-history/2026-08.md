# <a id="chg-20260806-01"></a>chg-20260806-01｜12B-2 测试入口 bat 编码问题修复与 bat 文件规范

## 问题

- 双击 `运行12B2完整流程实测.bat` 无法启动，控制台报 `'OT' 不是内部或外部命令`、`'it' 不是内部或外部命令`、`系统找不到指定的路径`，随后直接进入 `请按任意键继续`。

## 原因

- bat 内容含中文提示和 `chcp 65001`，文件以 UTF-8 保存；cmd 双击时按系统 GBK 代码页解析 UTF-8 字节，中文与全角标点的字节序列破坏命令解析（乱码字符吞掉换行），叠加 LF 行尾后整条批处理被拆成错误命令，并非 Python 程序问题。

## 调整

- 将 `运行12B2完整流程实测.bat` 改为纯 ASCII 内容、CRLF 行尾、无 BOM；移除 `chcp 65001`；中文提示改为英文。
- 保留 `%~dp0` 相对定位 Python 环境与输入目录，避免硬编码带空格绝对路径；若未来需要中文提示，改用 PowerShell 脚本或按系统 GBK 编码保存 bat。

## 验证

- 使用与正式 bat 相同结构（`%~dp0`、CRLF、纯 ASCII）的探针 bat 经 `cmd /c` 实际运行：解析正常、完整实测跑完、退出码 0；12B-2 协作取消与失败恢复场景均通过（失败堆栈为 QA 注入的预期日志）。
- Python 代码未改动；测试基线沿用 2026-08-06 实测结果。

## 影响与后续规则

- 影响范围仅限测试入口 bat，不涉及 Python 程序与业务逻辑。
- 后续新建或修改 `.bat` 必须：纯 ASCII（或按系统 GBK 编码保存）、CRLF 行尾、无 BOM；不使用 `chcp 65001` 与 UTF-8 中文混搭；需要中文提示时优先写入 `.ps1` 或项目文档。

# <a id="chg-20260806-02"></a>chg-20260806-02｜12B-2 分析完成未自动进入工作台修复

## 问题

- 正式 WebView2 工作台新建案件完整分析完成后，界面停留在“分析完成”进度页并显示“原案件仍保留，可返回审核工作台”，没有自动进入模块工作台。

## 原因

- 前端轮询回调先执行 `setAnalysis(completed)` 再异步获取案件头准备切换；`setAnalysis` 触发 effect 清理把 `stopped` 置为 true，`await getCaseHeader()` 返回后完成分支被 `stopped` 检查提前返回，切换逻辑没有执行。

## 调整

- 将 `completed + result_ready` 的完成处理移到 `setAnalysis` 之前：先获取案件头、写入完成提示、清空 preflight/analysis，再 `activateCase` 进入工作台并 dismiss 任务；非完成状态仍按原逻辑 `setAnalysis` 刷新进度。
- 实测脚本新增第三个场景：真实分析完整跑完后自动进入工作台（`.view-bar` 出现、模块数大于 0、案件会话切换为新案件）。

## 验证

- 前端 23 PASS；TypeScript 与 Vite 构建通过；真实 WebView2 窗口完整实测三个场景全部通过：协作取消、失败恢复、成功完成自动进入工作台（MVP-input 14 个来源全量完成，20006 笔交易，模块 9 个，前端错误 0）。

# <a id="chg-20260807-01"></a>chg-20260807-01｜12B-2 工作台底部显示修复：工作区滚动与分页脚固定

## 问题

- 带入客户资料后的“来源预检”页，底部“开始分析”一行被裁掉一半。
- 明细数据多时，底部“第 X / Y 页 · 上一页 / 下一页”分页脚不可见；数据少时可见。

## 原因

- `.work-area` 网格内容超出窗口高度时被外层 `overflow: hidden` 裁切，页面自身滚动无法覆盖全部溢出。

## 调整

- `.work-area` 增加 `overflow-y: auto`，任何模式（预检/分析/工作台）内容超高时整体可滚动，底部操作完整可见。
- `.list-region` 改为纵向 flex：`.issue-list` 内部滚动，`.page-footer` 固定在列表区底部，不随数据量变化被遮挡。

## 验证

- 实测脚本新增布局断言：预检页“开始分析”按钮滚动后完整可见；成功进入工作台后分页脚完整可见。
