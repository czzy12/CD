# 对手账号字段能力矩阵 v1

> 更新时间：2026-07-26
> 范围：各解析器向 `Transaction.counterparty_account` 提供可靠完整账号的能力。
> 判定边界：进入 v1C 还必须满足账号规范化后为 12 至 32 位数字、`field_confidence.counterparty_account == 1.0`、交易 ID 非空且交易非中性、非零收支。

## 状态定义

| 状态 | 含义 | v1C |
| --- | --- | --- |
| 可靠支持 | 来自独立表头列，或已有明确且已确认的固定分隔规则 | 满足完整账号门槛时可进入 |
| 仅 raw 保留 | 原文存在账号或混合对手信息，但不写入标准账号字段 | 不进入 |
| 明确排除 | 人工确认规则要求排除账号，或解析器显式清空标准账号 | 不进入 |
| 未确认 | 当前版式没有可靠拆列证据，不能从混合文本或相似版式推断 | 不进入 |
| 主动暂缓 | 已有争议或用户决定暂停，自动验证不执行 | 不进入 |

## 案件账户发现与对手账号能力的区别

- `StatementMetadata.account_number` 是流水文件抬头中的本方账号，用于案件账户自动发现；它不等于交易侧 `counterparty_account`。
- `bankflow_v2.case_accounts.discover_case_accounts()` 只接受抬头户名和账号均非空、置信度均为 1.0、账号为完整 12 至 32 位数字的结果。
- 文件夹只定义案件边界，不自动认定文件属于同一自然人；每个发现账户必须通过 `account_ref` 做一次角色确认。
- `verification_context_from_manifest()` 只把已确认角色的账户送入 v1C，用户不需要重新录入完整账号。
- `verification_context_from_manifest()` 同时保留已确认账户可靠的 `source_file_ids`，仅供 v1D 将交易来源文件精确归属到账户；缺少该映射时双边候选明确不可用。
