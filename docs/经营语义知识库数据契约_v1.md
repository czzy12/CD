## 一、版本注册

| 项目 | 值 |
| --- | --- |
| knowledge_version | business-semantic-kb-v1 |
| taxonomy_version | gb-t-4754-2017-core-v1 |
| semantic_kb_version | semantic-concepts-v1 |
| relation_kb_version | industry-relations-v1 |
| alias_kb_version | semantic-aliases-v1 |
| resolver_version | knowledge-v1-resolver-1 |

版本变化必须触发对应缓存失效或并存；分析结果必须能追溯所用 knowledge 版本。

## 二、Canonical 知识库（可提交 Git）

全部文件：UTF-8、稳定排序、可 diff、可人工 review、不依赖专有数据库。

### taxonomy.json

```json
{
  "format": "industry-taxonomy",
  "version": "gb-t-4754-2017-core-v1",
  "source": "GB/T 4754-2017《国民经济行业分类》(含2019年第1号修改单)",
  "source_version": "gb-t-4754-2017",
  "source_url": "https://openstd.samr.gov.cn/...",
  "scope_note": "只收录确认需要的节点，不声称覆盖完整分类",
  "updated_at": "…",
  "nodes": [
    {
      "industry_id": "51",
      "name": "批发业",
      "parent_id": "F",
      "level": 2,
      "aliases": ["批发"],
      "keywords": ["批发"],
      "status": "active",
      "source": "GB/T 4754-2017",
      "source_version": "gb-t-4754-2017",
      "knowledge_version": "business-semantic-kb-v1"
    }
  ]
}
```

约束：industry_id 唯一；parent_id 存在且无环；status 仅 `active / deprecated`；
官方节点 source 必须是官方标准来源，内部节点 source 必须是 `internal_knowledge_v1`。

```json
{
  "format": "semantic-aliases",
  "version": "semantic-aliases-v1",
  "aliases": [
    {
      "alias_id": "alias:运费",

```

约束：alias_id 唯一；同一 alias_text 不得映射到多个概念；concept 必须存在。

### relations.json

```json
{
  "format": "industry-concept-relations",
  "version": "industry-relations-v1",
  "relations": [
    {
      "industry_id": "internal.building_material_trade",
      "concept_id": "building_material",
      "relevance": "strong",
      "reason_template": "建筑材料是建材批发贸易的核心商品",
      "source": "curated_knowledge_v1",
      "review_status": "approved",
      "confidence_tier": "template",
      "knowledge_version": "business-semantic-kb-v1",
      "created_by": "knowledge_v1_bootstrap",
      "reviewed_at": "…"
    }
  ]
}
```

约束：industry 或 `generic_business` 必须存在；concept 必须存在；
relevance 只能五值；canonical 中 review_status 只能 `approved`；
同一 industry×concept 不得出现不同 relevance 的 approved 关系；
禁止 AI candidate 载荷（`proposed_value` / `new_concept_candidate` / `candidate` 状态）进入 canonical。

## 三、Runtime Cache（SQLite，不提交 Git）

位置：仓库外 `outputs/` 或 git 忽略目录，例如 `outputs/knowledge-v1-cache/knowledge_v1_runtime.db`。

### semantic_cache

```text
signature_version TEXT
signature_hash TEXT
concept_id TEXT
resolution_source TEXT
knowledge_version TEXT
review_status TEXT
created_at / updated_at / hit_count
PRIMARY KEY (signature_version, signature_hash)
```

### relation_cache

```text
taxonomy_version TEXT
industry_id TEXT
concept_id TEXT
relation_rules_version TEXT
relevance TEXT
relation_source TEXT
knowledge_version TEXT
review_status TEXT
created_at / updated_at / hit_count
PRIMARY KEY (taxonomy_version, industry_id, concept_id, relation_rules_version)
```

### candidates

```text
candidate_id TEXT PRIMARY KEY
candidate_key TEXT UNIQUE（候选内容指纹，去重）
candidate_type TEXT（new_semantic_concept | new_industry_relation | new_alias）
proposed_value_json / reason / model / prompt_version
input_signature_json（只含哈希与 ID，不含客户敏感原文）
created_at / review_status（pending | approved | rejected）/ reviewed_at
```

语义缓存只保存规范化语义签名哈希；真实案件语义文本只以 hash 进入运行缓存。

## 四、KnowledgeCandidate 审核

AI 或 legacy 迁移生成的候选：

- 先进入 `pending`；
- 人工确认后 `review_knowledge_candidates.py approve <id>` 才 promote 到 canonical JSON；
- `reject` 进入 `rejected`，不进入正式知识；
- promote 写入 canonical 时自动刷新版本文件中的 `updated_at`。

## 五、Validator 检查清单

- ID 唯一（行业/概念/别名/关系）
- parent 存在、无循环
- alias 冲突检测
- relation 引用存在
- relevance 枚举
- canonical 只允许 approved
- deprecated 引用
- 版本字段存在
- 同一 industry×concept 的 strong/none 冲突
- source 缺失
- AI candidate 误入 canonical
- 客户敏感数据模式（身份证、银行账号、电话、本地路径）命中即失败
