# 经营语义知识库架构 v1（knowledge_v1）

更新：2026-08-07

## 一、目标与定位

当前经营相关性 AI（`business-relevance-mvp-v11`）以“客户案件上下文 + 语义签名 + AI 缓存”为复用单位，
新客户、新行业会继续产生重复模型调用，且缓存键实际包含案件业务上下文（input_fingerprint 兼容校验），
跨客户复用被限制。

knowledge_v1 把长期架构调整为四层知识体系，让 AI 从正式客户主链上的“判断者”转变为知识库的“增量补洞工具”：

```text
旧架构：
Customer Context + Semantic Signature → AI Business Relevance Cache

新架构：
Transaction Text
  → Semantic Concept（通用经营语义）
  → Industry Normalization（标准行业）
  → Industry × Concept Relation（行业×语义关系）
  → strong / medium / weak / none / undetermined
  → 经营痕迹候选
```

最终目标：绝大多数新客户分析 0 次 AI 调用；出现新语义只调用未知语义；
出现新行业关系只调用未覆盖关系；人工确认一次后永久复用。

## 二、既有 AI 实现审计结论（2026-08-07，只读审计）

审计范围：`bankflow_v2/deepseek_adapter.py`、`bankflow_v2/ai_business_observation.py`、
`tools/run_ai_sample_acceptance.py`、`tools/run_ai_full_acceptance.py`、
`tools/replay_ai_response_cache.py`、`tools/audit_ai_semantic_inputs.py`、`bankflow_v2/result_export.py`、
`bankflow_webview2/api.py`、`bankflow_web/analysis/`、相关测试与验收产物目录。

1. task_type：`business_relevance`。
2. prompt 版本：`business-relevance-mvp-v11`。
3. output contract 版本：`semantic-judgement-v2`。
4. AI 输入字段（白名单）：`counterparty_name / summary / remark / purpose / product_description / merchant_name / merchant_category`；
   另有可追溯但不可单独作行业证据的 `transaction_type / transaction_method / payment_method`。
5. AI 输出字段：`semantic_judgement（五值）/ reason / used_fields`；分类与强度由本地派生并二次校验。
6. 缓存键实际组成：`task_type + provider + model + prompt_version` 命名空间 + 规范化语义签名 ID；
   但 `input_fingerprint` 与 legacy 兼容校验都要求 `business_context` 相等，
   因此案件业务上下文事实上进入缓存命中判定（客户级缓存污染）。
7. 缓存位置：`%LOCALAPPDATA%\BankFlowReview\ai-response-cache`（signatures/ 与 requests/，无凭据）。
8. AI 批大小：默认 50（`BANKFLOW_AI_BATCH_SIZE`）。
9. AI 默认开关：进程内持久化配置齐备且显式加载后启用；正式工作台分析固定 `replay_only=True`（零网络）。
10. AI 结果进入经营候选：经 `build_ai_business_observation` 聚合为
    `ai_business_relevance_candidates` 观察，写入 schema 1.16 标准结果。
11. 本地硬护栏：`classification_constraints`（`directly_related_allowed`、
    `directly_related_evidence_fields`、`maximum_allowed_strength`、`deterministic_non_business_category`）
    在模型前生成，模型后由 `validate_ai_response_collecting` 强制复核。
12. 离线重放：`DeepSeekEvaluator(replay_only=True)` 只读缓存，未命中即降级并记录 `cache_miss`。
13. 已验收语义数量：曹国民完整 286 种唯一语义 / 1115 笔展开；任如冰固定 20 种；李娟 20 种；
    development 50 / reserved 50 固定样本另计。运行时缓存合计 334 个签名文件。
14. 客户级缓存污染：存在（business_context 进入命中判定），是本次改造的核心对象。
15. 强依赖旧缓存结构的模块：工作台 AI 状态面板（缓存条目数）、`replay_ai_response_cache.py`、
    `tools/run_ai_sample_acceptance.py` / `run_ai_full_acceptance.py`（固定样本清单）。

## 三、四层正式知识体系

### A. Industry Taxonomy（行业标准化）

- 官方来源：GB/T 4754-2017《国民经济行业分类》（含 2019 年第 1 号修改单），现行有效；
  2025 年修订仍处于国家标准项目计划，未发布，未采用。
- 本阶段只收录确认需要的官方门类/大类节点与内部细分节点，不声称覆盖完整分类。
- 官方节点 `source=GB/T 4754-2017`；内部细分节点 `source=internal_knowledge_v1`。
- 实体：`IndustryNode`（industry_id / name / parent_id / level / aliases / keywords / status / source / source_version / knowledge_version）。

### B. Semantic Concept KB（通用经营语义库）

- 实体：`SemanticConcept`（concept_id / name_zh / aliases / keywords / parent_concept_id / description / examples_generic / status / source / knowledge_version）。
- `examples_generic` 只含脱敏泛化示例，禁止真实客户姓名、完整企业名、账号或敏感交易。
- 初始 55 个概念，覆盖商品、服务、经营投入、结算、泛化弱提示、生活消费六大类，含父子层级。

### C. Industry × Concept Relation KB（行业/语义关系库）

- 实体：`IndustryConceptRelation`（industry_id / concept_id / relevance / reason_template / source / review_status / confidence_tier / knowledge_version / created_by / reviewed_at）。
- relevance 只使用五值契约：`strong / medium / weak / none / undetermined`。
- review_status：`approved`（生产离线默认只使用）；AI 生成一律 `candidate`，验收后经 promote 进入 canonical。
- 初始 261 条人工编写模板关系（bootstrap approved），正式生产前仍需人工验收复核。

### D. Semantic Alias / Examples（表达→概念映射）

- 实体：`SemanticAlias`（alias_id / alias_text / concept_id / status / source / knowledge_version）。
- 只保存通用别名与脱敏泛化表达；真实客户原始表达不得进入 Git 知识库。
- 初始 123 条通用别名。

## 四、解析顺序

### SemanticResolver

1. deterministic exact rule（整值别名精确命中）
2. approved semantic alias KB（关键词命中，按直证字段优先级）
3. approved semantic signature cache（signature_version + signature_hash）
4. parent/general concept resolution（概念父级只参与追溯，不改变概念 ID）
5. AI fallback（仅显式授权；`semantic_concept_resolution`）
6. undetermined（AI 关闭时未知项安全返回，不猜测）

### IndustryRelationResolver

1. exact approved industry × concept
2. specialty relation（行业画像明确列为专项概念时，通用关系封顶 medium）
3. parent industry inheritance（保守继承，标记 `relation_source=inherited`，不自动升级）
4. generic business relation（`generic_business` 锚点，绝大多数生活概念为 none）
5. AI relation fallback（仅显式授权；`industry_concept_relevance`）
6. undetermined

最终统一经过现有本地护栏：`maximum_allowed_strength` / `directly_related_allowed` 强制封顶。

## 五、缓存双轨

### Semantic Cache

Key：`semantic_signature_version + semantic_signature_id`。
Value：concept_id / resolution_source / knowledge_version / review_status。
客户身份、案件 ID、行业均不得进入 Key。

### Relation Cache

Key：`taxonomy_version + industry_id + concept_id + relation_rules_version`。
Value：relevance / reason / source / review_status / knowledge_version。
不得加入 customer_id、case_id、姓名或案件唯一值。

正式知识库（canonical JSON）与运行缓存（SQLite，仓库外或 git 忽略目录）严格分离。

## 六、父级继承

- 新子行业先查本行业 approved 关系；
- 不存在则沿父链查找，命中即继承并标记 `inherited`；
- 继承不自动升级强度（父 strong 不无条件给子行业 strong）；
- 父行业也无可靠关系时才进入 generic / AI / undetermined；
- 所有继承逻辑有测试覆盖。

## 七、Shadow Mode

`knowledge_v1_shadow_mode`：对现有 approved 测试样本同时输出 legacy_v11 与 knowledge_v1，
生产结果仍由 legacy 决定。对比指标：

- 一致率（agreement rate）
- 不一致数（disagreement count）
- 新增 undetermined 数
- 相对 legacy 强度上调数（strength escalation）
- 生活类正向样本数（life positive，本实现由硬护栏保证为 0）
- 非法字段引用 / 强度越界 / AI 风险结论（通过 validator + 硬护栏机械检查）

不追求与旧模型逐条理由一致；确定性业务规则、五值契约、强度护栏、生活类排除必须保持不变。

## 九、边界与停止条件

- 不修改 schema 1.16；知识层字段只存在于内部 DTO / diagnostics / 运行缓存。
- 不修改确定性业务规则；不删除 legacy_v11；不改旧 fixture。
- 不把客户身份加入任何缓存 Key；不上传客户敏感数据。
- AI 默认关闭；`allow_ai_fallback=false` 时未知项安全 undetermined。
- AI candidate 不自动 approved；未经人工验收不得进入 canonical。
- taxonomy 来源已确认且本地化；生产运行时绝不联网获取行业资料。
- 出现上述任一违背即停止并汇报，不绕过。
