## 三、验收目标核对

1. 客户身份不参与缓存 Key：是（语义 Key = signature_version + hash；关系 Key = taxonomy + industry + concept + rules）。
2. Semantic Concept 跨客户复用：是（概念层与行业解耦）。
3. Semantic Concept 跨行业复用：是（同一概念用于多个行业关系）。
4. 行业关系跨客户复用：是（关系 Key 无客户维度）。
5. 父行业关系可继承：是（`inherited` 标记 + 保守不升级，有测试）。
6. 未知项 AI 关闭安全 undetermined：是。
7. AI 开启只增量调用：契约已定义（semantic / relation 两个 fallback），本轮未执行真实调用。
8. AI candidate 不自动进入生产：是（candidate → pending → promote 才进 canonical）。
9. approved 一次后下一案件零 AI 调用：设计成立（relation cache + canonical approved），测试覆盖 approved 命中。
10. legacy_v11 可完整 shadow 比较：是（326 条真实缓存离线对比）。
11. 旧确定性业务结果不变化：是（未触碰确定性观察与 schema）。
12. AI 字段安全边界不变化：是（沿用同一白名单，adapter 增加出站过滤测试）。
13. schema 1.16 不变化：是（本轮未修改 schema）。

## 五、schema 1.17 设计草案（仅建议，未实施）

本阶段未修改 schema 1.16。基于 knowledge_v1 运行结果，以下字段确实具备长期保存、
审计与跨会话复用的价值，建议在正式切换前进入 schema 1.17 讨论：

```json
{
  "business_semantics": {
    "concept_id": "logistics",
    "concept_name": "物流运输",
    "industry_id": "internal.building_material_trade",
    "industry_name": "建材批发贸易（内部细分）",
    "relevance": "medium",
    "resolution_source": "knowledge_base",
    "knowledge_version": "business-semantic-kb-v1",
    "review_status": "approved"
  }
}
```

建议位置（三选一，需用户确认）：

1. 附加在现有 `ai_business_relevance_candidates` 观察的每个候选条目上（最小侵入）；
2. 作为新的 `result.observations[]` 类型（`business_semantics_resolutions`，影子/正式可选）；
3. 作为标准结果顶层 `diagnostics` 的只读元数据（最保守，不进入业务观察）。

升级流程：

```text
knowledge_v1 shadow 验收通过
  → 确认必须持久化的字段
  → 设计 schema 1.17
  → 单独 migration
  → 1.16 / 1.17 兼容测试
  → GUI 切换
```

禁止边做边往 1.16 塞字段；1.17 方案需用户确认后单独实施。
