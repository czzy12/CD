# PDF 流水解析踩坑与通用规则

> 本文件只保存跨银行仍然有效的防错规则。具体某次问题的背景、失败尝试和验证证据，请按变更 ID读取《技术变更记录》归档。

## 样本与回归通用规则

- 主要样本根目录：`D:\Codex data\CD_assets\PDF流水`、`D:\Codex data\PDF流水`。
- 项目回归配置、技术变更记录和本手册明确引用的其他现存路径可加入盘点；若文件已存在于主要根目录或内容完全相同，只记录路径别名，不重复解析。
- 完全重复优先按 SHA-256 识别；二进制不同但内容相同的 PDF，再按标准化文本或解析后的交易指纹识别。
- 同一银行、同一账户的不同月份文件不是重复样本：每个文件保留单文件回归，同时建立跨月组合回归，检查日期顺序、重叠交易、余额连续性和月度汇总。
- 部分月份重叠或重复导出的流水，组合时去重但不得改变单文件解析结果；去重必须保留来源文件、页码、行号和原始字段。
- 本阶段以原始 PDF 解析为主要基线。人工整理且只保留数字的 Excel 标记为辅助数字参考，不用于交易对手、摘要、备注等文字字段验收；图片 PDF 转 Excel 在来源和准确性未确认时列为待核实。
- 已纳入正式自动回归的 Excel 继续单独运行，确保 PDF 文字字段重构不破坏既有 Excel 导入能力。
- 样本目录保持只读；批量验证、清单、哈希、日志和报告写入独立输出目录。
- 新银行适配仍需同时更新 `auto_detect.py`、`pipeline.py`、解析器、回归案例、本手册和 `技术变更记录.md`。

## 核心问题与解决规则

### 2026-05-30 工行对公企业存款对账单新版式

**现象**: 4 份 `中国工商银行企业存款对账单` 被识别为工行对公，但专用解析返回 0 笔，GUI 回退到通用识别后出现大量余额不连续。

**原因**: 表头只有 `借方发生额 / 贷方发生额 / 余额`，没有旧版工行对公依赖的 `借/贷` 或 `借贷标志` 列。

**修复**:

- 自动识别新增关键词：`中国工商银行企业存款对账单`
- `icbc_corp.py` 新增 format C
- format C 按 `借方发生额=支出`、`贷方发生额=收入`、`余额=余额链校验`
- 4 份样本加入 `tools/regression_cases.json`

**验证**: 4 份李翠样本全部 0 异常，统一回归 `14 PASS / 0 FAIL`。

### 2026-05-29 中信、民生对公、Excel 导入与小额余额差异

**中信个人**:

- 新增 `citic.py`
- 支持 `账户交易明细 / Transaction details`
- PDF 文本层只有单金额列时，使用上一笔余额判断收入或支出

**民生对公**:

- `单位账户对账单` 优先识别为 `民生银行对公`
- 避免被通用民生关键字误识别为个人

**Excel 导入**:

- 支持 `借贷状态`
- 保留银行原始借/贷列口径
- 借方负数冲正仍按支出列口径统计，方便和人工透视表一致

**小额余额差异**:

- Excel 导入和通用 PDF 识别中，0.99 元以内余额连续性差异标为 `低风险`
- 低风险不再把文件状态打为 `需复核`
- 专用银行解析器仍保持严格复核标准

### 1. PDF乱码金额 — `clean_number` 三次迭代
**现象**: 工商银行PDF金额列混入随机字符（如 `04-59.90`、`40:5-29.70`）
**v1**: `re.search` 第一个匹配 → 乱码前缀被误认为金额
**v2**: 优先匹配 `[+-]\d+\.\d{2}` → 部分解决
**v3**: `re.findall` 取最后一个匹配 → 解决大部分
**v4**: 余额交叉验证 → 解决数字粘合（`1426.19` → `146.19`）

### 2. 余额交叉验证
**文件**: core/extractor.py `_validate_with_balance`
**原理**: `余额变动 = 当前余额 - 上笔余额`，与解析金额对比
**安全机制**: 比值限制0.05x~20x，过滤不可靠余额

### 3. 银行检测加权
**现象**: 短关键词（"工行"、"ABC"）在乱码中误匹配
**修复**: 改为关键词长度加权 `score = sum(len(kw) for kw in matched)`

### 4. 四舍五入误差
**现象**: 月度值先舍入再求和 → 合计行与余额行不一致
**修复**: 合计行从原始DataFrame计算，不累加月度值

### 5. 跨页表头缺失
**现象**: 浦发仅首页有表头
**修复**: `_cached_col_match` 缓存首页匹配

### 6. 跨行文本配对
**现象**: 民生对公PDF每笔交易跨两行（日期/时间分离）
**修复**: `text_line_pair: true` 配置项，相邻行合并

### 7. 借贷方向反转
**现象**: 个人户借方=支出，对公户借方=收入
**修复**: 配置项 `debit_is` 控制

### 8. 文本行乱码过滤
**现象**: 农业、民生PDF乱码行被正则误匹配
**修复**: 验证日期+时间前缀格式，不匹配则跳过

### 9. 时间排序
**现象**: 同日交易未按时间排序
**修复**: 捕获time字段，复合排序

### 10. 表格复制
**现象**: QTableWidget Ctrl+C只复制当前格
**修复**: 子类化CopyableTable，遍历选中区生成制表符文本
